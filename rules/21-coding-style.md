# 21-coding-style (클린 코드 스타일 및 구현 표준)

> **원칙**: 코드는 읽는 사람을 위해 작성합니다. 단순함이 기교보다 우월하며, 깊은 중첩과 불필요한 추상화를 배제합니다.

---

## 1. 제어 흐름 및 중첩 제어 (Guard Clause & Early Return)
- **조기 반환(Early Return) 준수**: 조건 불만족 시 즉시 반환하여 메인 로직의 들여쓰기 깊이를 최대 2단계 이내로 유지합니다.
- **불필요한 `else` 제거**: `if` 블록 내부에서 `return` 또는 `throw`가 실행된다면 후속 `else`나 `else if`는 작성하지 않습니다.
- **방어적 단언(Guard Clause)**: 함수의 진입점에서 인자 유효성 및 사전 조건을 먼저 검증합니다.

---

## 2. 가독성 및 함수 설계
- **단일 책임 원칙(Single Responsibility)**: 하나의 함수는 하나의 명확한 작업만 수행합니다. 함수가 50줄을 초과하면 분리를 검토합니다.
- **부수 효과(Side-Effects) 최소화**: 순수 함수(Pure Function) 작성을 지향하고, 전역 상태나 외부 객체의 직접 변경을 지양합니다.
- **매직 넘버/스트링 금지**: 의미를 알 수 없는 숫자나 문자열 리터럴은 명명된 상수로 추출하여 선언합니다.

---

## 3. 주석 및 자기 설명적 코드
- **불필요한 주석 배제**: 코드가 무엇을 하는지 단순히 반복하는 주석은 달지 않습니다.
  - 나쁜 예: `// i를 1 증가시킴` `i += 1;`
  - 좋은 예: 비즈니스 결정 이유, 알고리즘 선택 배경, 버그 회피 사유 등 'Why'를 설명하는 주석
- **기존 주석 및 문서 보존**: 리팩토링 중 기존 작성자의 의도된 주석이나 API 문서를 임의로 삭제하지 않습니다.
