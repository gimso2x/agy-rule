# 22-generic-spec-standard (일반 스펙 명세 표준)

> **원칙**: 구현 전 명세가 불명확하면 코드는 반드시 방황합니다. 복잡한 기능 구현 전 5대 표준 섹션을 갖춘 명세서를 먼저 수립합니다.

---

## 1. 스펙 명세서 필수 5대 섹션
신규 모듈이나 복잡한 기능을 설계할 때 아래 구조를 준수하여 작성합니다:

1. **문제 정의 (Problem Context)**:
   - 해결하려는 문제의 현상과 배경을 명확히 서술합니다.
2. **목표 및 비목표 (Goals & Non-goals)**:
   - **Goals**: 이번 작업에서 반드시 달성해야 하는 범위
   - **Non-goals**: 이번 작업 범위에서 의도적으로 배제하는 항목 (오버엔지니어링 차단)
3. **인터페이스 및 데이터 모델 (Interfaces & Schemas)**:
   - 입력과 출력, 함수 시그니처, API 엔드포인트, DB 스키마 정의
4. **예외 처리 및 엣지 케이스 (Edge Cases & Errors)**:
   - 네트워크 장애, null/undefined, 타임아웃 등 실패 시나리오 및 복구 전략
5. **검증 계획 (Verification Plan)**:
   - 단위 테스트, 통합 테스트 또는 수동 검증 시나리오 명시

---

## 2. 문서화 및 보존 규칙
- 수립된 스펙은 `.harness/plans/` 또는 작업 아티팩트로 저장하여 영구 자산화합니다.
- 요구사항 변경 시 스펙 문서를 먼저 갱신하고 코드를 수정합니다.
