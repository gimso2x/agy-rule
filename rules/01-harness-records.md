# 01-harness-records: 하네스 기록 체계 및 지식 자산화 지침

## 1. 목적
- 에이전트와의 세션은 일회성으로 소멸되지 않으며, 모든 의미 있는 산출물은 프로젝트 및 전역 지식 자산으로 축적되어야 합니다.
- 임의의 임시 폴더에 무분별하게 파편화하지 않고, 정형화된 `.harness/` 디렉터리에 체계적으로 저장합니다.

## 2. 디렉터리별 기록 원칙
- **`plans/`**: 복잡한 작업이나 4단계 이상의 태스크 수행 전 작성된 Action Plan 보관.
- **`audits/`**: 코드베이스 무결성, 보안, 규칙 준수, 파일 크기 한도 측정 보고서 보관.
- **`memory/`**: 프로젝트 특화 도메인 지식, 사용자 선호 패턴, 영구 보존용 에이전트 메모리.
- **`handoff/`**: 작업 세션 종료 시 다음 세션 또는 다른 에이전트와의 원활한 인수인계를 위한 상태 스냅샷.
- **`history/`**: 주요 마일스톤 및 아키텍처 결정(ADR) 이력.
- **`pull-request/`**: PR 제출용 변경 명세, 영향도 분석서.
- **`walkthroughs/`**: 변경된 기능에 대한 단계별 검증 절차 및 실행 워크스루.

## 3. 운용 수칙
- 파일명은 날짜 또는 일련번호를 포함하여 정렬 가능하게 명명합니다 (예: `2026-09-26-harness-init.md`).
- 산출물 작성 후 반드시 저장 경로를 사용자에게 안내하고 Git 버전 관리 대상에 포함시킵니다.
