# 05-meta-labels (메타 라벨 및 태그 표준화)

> **원칙**: 메타데이터는 시스템과 사람이 변경 사항의 성격을 즉시 식별할 수 있도록 돕는 규약입니다. 일관된 접두사와 태그 형식을 엄격히 준수합니다.

---

## 1. Git 커밋 메타 라벨 (Conventional Commits)
커밋 메시지 제목은 아래 표준 접두사 중 하나를 반드시 사용합니다:
- `feat:` 신규 기능 추가 또는 사용자 인터페이스 변경
- `fix:` 버그 수정 또는 오동작 해결
- `docs:` 문서, README, 주석의 추가 및 수정
- `refactor:` 동작 변경 없는 코드 구조 개선 및 정리
- `test:` 테스트 코드 작성, 보강, 픽스처 추가
- `perf:` 성능 개선 및 리소스 최적화
- `chore:` 빌드 설정, 의존성 패키지 관리, 보일러플레이트 작업

---

## 2. 하네스(.harness) 및 로그 표준 태그
작업 기록, 인수인계서, 의사결정 문서 작성 시 아래 태그를 머리말이나 섹션에 명시합니다:
- `[CHECKPOINT]`: 사용자 확인이 필요한 필수 정지점 기록
- `[DECISION]`: 아키텍처 또는 라이브러리 선정 등 기술적 의사결정 기록
- `[AUDIT]`: 정합성 감사, 보안 점검, 코드 품질 검사 결과
- `[HANDOFF]`: 세션 종료 또는 다음 작업자를 위한 상태 인수인계
- `[METRIC]`: 벤치마크, 라인 수, 바이트 용량 등 정량적 수치

---

## 3. GitHub Alert 블록 가이드라인
문서 작성 시 GitHub Flavored Markdown의 알림 블록을 적재적소에 활용합니다:
- `> [!NOTE]`: 배경 맥락이나 참고 정보 제공
- `> [!IMPORTANT]`: 필수 준수 요구사항 및 핵심 제약 조건
- `> [!WARNING]`: 호환성 파괴, 성능 저하 등 주의가 필요한 사항
- `> [!CAUTION]`: 데이터 손실, 환경 파괴 등 고위험 작업 경고
- **주의사항**: 알림 블록을 연속해서 중복 배치하거나 과도하게 남발하지 않습니다.
